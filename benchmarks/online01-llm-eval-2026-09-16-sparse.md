## What the run found: a live defect on the whole target scope (D9)

The first run refused **every** attempt:

```
2 request(s), 4 provider call(s): 0/2 answered (re-sampled: 0), rejected: 4
  ! rejected: LLMOutputRejectedError: Model cited fact references outside the allowed input set.
```

The model's text was not the problem — it was the honest answer ("no source entries
were supplied: the coverage list is empty and the sources list is empty, so no
per-source retrieval status can be reported for any database"). The refusal was a
**citation-contract bug**: the only refs it cited were `target:<id>`, which is
legal, and `reference:<id>`, which was not.

- The target prompt instructs the model, in the shipped system prompt: *"Cite
  `reference:<id>` for any statement about potency or about the set being usable or
  not."*
- `ai.allowed_refs()` enumerated `family`, `document`, `target` and five item lists.
  It never walked the `reference` node, so `reference:<id>` was never in the
  allowed set (`allowed_refs: 1` in the before-fix record).
- The failure mode is therefore not sparse-specific: **any** target summary whose
  model followed its potency instruction was refused. The sparse scope is simply
  the case where the model has almost nothing else to cite, so it fired 4/4.

`ai._build_citations()` had the same hole from the other direction: had the ref
been allowed, a `reference:` citation would have been accepted and then silently
dropped from the citation list — the reader would lose the support link for the one
number the summary is allowed to repeat.

**Fix.** `allowed_refs` now walks the snapshot generically and collects every `ref`
/ `family_ref` key it finds; `_build_citations` maps the `reference` node to a
`reference` citation carrying the target id and a label with the count, threshold
and policy version. The rule is now the one the prompt states, and there is no
second list to drift. UI: a `reference:<target-id>` citation click scrolls to and
flashes the verdict strip (same rule the `source:<name>` citation already used)
instead of falling through to the evidence tab. Regression test:
`test_the_potency_verdict_ref_is_citable_and_reaches_the_reader`.

## After the fix: 2 of 2 answered, and the text is honest

`allowed_refs: 2` (target + reference). Both attempts were accepted on the first
call, no re-sample, 4,347 tokens total, median call latency 3,632 ms.

What the accepted summary says about a scope with nothing in it — this is the
behaviour `docs/online-capability.md` §5 promises ("a thin set is never reported as
a negative result"):

> "The input contains no source records: the sources array is empty and the coverage
> array is empty, so no per-source retrieval status, count or warning is available
> for this investigation."
>
> "…the reference does not qualify (qualifies false) … This is a deterministic count
> of stored records at or below the stated threshold, **not a biological conclusion
> and not evidence that no other inhibitor exists**."
>
> "An empty patent list is not proof that any compound is unclaimed."

No paragraph claims absence of inhibitors, and none presents the empty set as a
finding about the literature.
