日期：2026-09-15。基线：本地与远端 `main` 均为 `f3da90c`，加上开始检查时已经存在的未提交修复、测试和文档。状态：**评估及计划完成，以下产品补齐工作尚未实施**。本轮只修改文档，保留全部已有代码改动；未提交、推送、重建服务或更改运行数据。

## 1. 发布判断与首版边界

**目前可用于合成数据演示和开发验证，尚不能作为真实专利分析产品交付。** 分页、化学检索和可选摘要的基础已经存在；主要阻碍是实际数据入口、结果范围、保存后继续工作和交付保障，而非再加几个界面。

首个交付目标定为：**本地、单用户、单 app worker、覆盖范围明确的真实专利化学查看器**。用户通过容器启动，输入已覆盖的真实公开号或导入支持的数据包，检查结构和证据，筛选、保存、重新打开项目、导出并在重启后继续工作。数据覆盖之外明确说明“当前来源未覆盖”，不能承诺任意专利均可查。

| 使用方式 | 当前结论 | 发布门槛 |
| --- | --- | --- |
| 合成数据演示 | 可以；本轮查询/结构筛选可运行，来源明确标为 Demo | 只用于产品流程反馈，不作为科研数据或真实模型验收 |
| 本地单用户真实专利工作 | **不通过** | 下述 CORE 项 PROD-01–05 及 G1 验收通过 |
| 带真实活性/SAR 或 LLM 的版本 | **不通过对应能力验收** | 在 G1 上分别增加 PROD-06/07；无活性不能解释为无活性，无 LLM 配置仍能完成查看器流程 |
| 多用户/LAN/托管服务 | **不通过** | G1 加 PROD-08 的认证、授权和部署验收；登录网关本身不提供项目隔离 |

Ketcher 绘图和 Chrome 扩展是后续增强，不应阻塞已经明确支持 SMILES 输入的单用户查看器。PDF/OCSR、自由聊天、广域 SAR、完整 Markush、FTO 定论不属于本轮发布门槛。

## 3. 欠缺事项与执行计划

### PROD-01 / CORE / P0：真正的数据入口和可核对证据

阻碍：当前交付只包含 synthetic fixture；`SureChemblFixtureAdapter`、启动 seed 和部分 UI 文案按演示数据固定。把真实记录塞进同一 fixture 并改 Demo 标签，不构成来源接入。

- **第一步**：选定一个最小真实专利案例和一种主化学数据来源，核实当前官方接口/数据格式、可用范围、版本和使用条件。复用现有 adapter→domain→service→API，不同时铺开所有来源。候选为官方结构化接口/版本化批量子集或用户明确提供的来源包；具体来源核对后才进入实现，不将本计划视作外部 schema 已确认。
- 将迁移和 demo seed 的启动职责分开；真实/演示来源有显式部署方式，真实模式重启不再自动混入 fixture。提供用户可完成的导入/覆盖说明路径；不要求科研用户改 Python、手工 SQL 或伪造 Parquet。超过交互预算的导入使用 PostgreSQL 持久 job 与有界批次，不增加队列服务。
- 保存 source/source-record ID、版本、检索时间、文件校验、归一化决策及失败/部分覆盖状态；TopBar、表尾、保存提示和 dataset API 根据实际来源显示，不硬编码所有数据为 Demo。保持结构、mention、同族、证据的不同身份。
- **关闭依据**：一个真实案例完成公开号→同族→结构→原始来源记录核对；再用至少一个不同同族和一个缺结构/缺证据案例检查串族及缺失状态。人工对照选定结构、局部标签、立体信息和来源定位；重复导入不重复，错误/限流不伪装成空成功。数据库关联缺页码时明确标注，不虚构原文位置。
- **依赖/产物**：来源选择 Q&A、已有适配/入库服务的定向扩展、最小可公开回归夹具及独立科学核对；私人数据保持本地。一例通过仅准许该覆盖范围试用，不宣称广泛覆盖。

### PROD-02 / CORE / P1：筛选、导出和来源范围一致

阻碍：结构查询剩 1 条，当前结果导出 10 条。`services/export.py` 的来源聚合还查询化合物全部 mentions/evidence；加入多个真实同族后必须明确哪些属于当前范围，不能暗中混为当前专利证据。

- 先固定本轮 1→10 的失败回归，再统一已显示查询与导出服务的作用域。优先让服务端接收可校验的结构条件/查询范围，并覆盖尚未加载的匹配记录；不得把当前加载页 ID 当作全部结果。
- 若当前阶段只提供 family/document 导出，必须明确命名范围，并在无法表达结构筛选时禁用“当前结果”及解释原因；明确所选导出始终可用。不得只增加一个名字不同但仍误导的重复按钮。
- 为源记录标明当前 scope 与外部关联；校验 selected IDs 属于请求 family/document 的契约，拒绝或明确报告越界 ID。
- 5000 条同步上限须在 SQL 有界查询/计数阶段实施；目前先 `.all()` 后检查长度，不能将此称为内存保护。超限明确拒绝；大导出任务可后置。
- **关闭依据**：普通/文档/结构过滤、所选、>100 与 >500 分页情况下 CSV/SDF 的键集合和来源范围等于声明范围；跨同族相同分子不混证据；超限在全量装载前被阻止；浏览器下载与 API 输出共同核验。覆盖保存/导出失败后的选择保留。

### PROD-03 / CORE / P1：保存后重新打开，来源版本不漂移

阻碍：有持久数据但无项目重开 UI；保存版本来自客户端，项目读取又连接当前 compound 字段。后续数据更新时“旧版本标签+新字段”存在源码风险，本轮未做数据库反例。

- 复用现有项目 API和工作台，增加一个按需项目选择/打开入口，使保存→关闭页面→重开项目→检查来源可完成。无需先做独立项目仪表盘、组织管理或新的永久侧栏。
- 服务端从实际保存范围校验/导出来源版本，不信任任意客户端 `dataset_version`；多来源多版本保留完整清单。写入前明确引用还是快照语义；本地首版优先保存可追溯版本引用，数据更新不得静默替换其含义，失效明确提示。
- 任何需要的 schema 变更配前向迁移，旧项目归属和来源不丢失；保存成功仅在持久记录可读后报告。
- **关闭依据**：跨两次浏览器会话和容器重启重新打开项目，所存 family/compound/证据/版本匹配；重复保存幂等、非法版本拒绝、来源更新/缺失可解释；项目无数据、读取失败和保存重试可用。测试必须通过可见入口完成，不能只凭数据库有行。

### PROD-04 / CORE / P1：本地交付的默认网络与恢复能力

阻碍：数据库实际监听全部宿主接口；当前未找到整产品备份/恢复说明或演练记录。已有命名卷和 0005→0006 测试应保留，不能称为“完全没有持久化或升级测试”。

- 默认数据库只走 Compose 内网，或为开发保留显式回环端口；应用维持回环、单用户、单 worker。演示密码与真实部署配置有清楚边界，不把本地应用入口误当作数据库也已隔离。
- 提供最小备份/恢复操作，覆盖数据库中的项目、证据、来源版本和分析，外部来源文件另记录可恢复位置/校验；描图缓存可重建，无需备份为科学证据。
- 在独立目录、网络和数据卷中演练干净安装、旧版本升级、备份恢复与重建后读取；比对记录内容和引用，不仅检查容器 healthy。全程不清空用户运行数据库。
- **关闭依据**：新机器仅按文档 Compose 即可启动；默认 app/DB 从 LAN 不可访问；备份恢复后的项目可通过界面重开；一次已支持版本升级保留数据，回退/恢复步骤明确并实际可用。

### PROD-06 / NEXT；若发布活性/SAR 则必需：真实活性接入与测量合同

当前 ChEMBL/BindingDB 类不是已接通的导入产品：`seed.py` 只用 BioactivityFixtureAdapter；需要将规范化测量接入真实记录的持久化、API 与证据回跳。

- 先完成一种真实来源，不同时重写两个适配器。核对原始 assay/source-record ID、单位、关系符、测定条件和目标映射，化合物通过确定性身份映射，数据库测量不能当成专利原文证据。
- 源码需修正/验证的边界：ChEMBL 缺 `standard_units` 时默认 `nM`、缺 `relation` 默认 `=`；BindingDB 将单位固定为 nM、以目标名构造 assay_key，可能合并同目标不同实验。来源不足应标缺失/拒绝并保留原因，不能猜测科学字段。
- 独立源码核验还发现 BindingDB 用文件内行号作 record ID、导入日期作版本；原 seed 写入用 record ID 派生 measurement UUID，不能原样用于不同真实文件。需验证稳定来源身份、同文件重导/重排及不同文件相同行号不碰撞；API/UI 暴露逐条来源记录及回跳，补齐非法/非有限值、缺 ID 和分页截断的可见错误。
- **关闭依据**：逐条对照少量真实测量，涵盖不同 assay、单位/关系符、缺值、未匹配结构；原始值/规范化值/来源保持可追溯，失败/部分结果可见。无数据不显示活性断言，不自动产生跨 assay 排名或选择性。
- 若首版本明确只交付结构查看器，可先不提供真实活性/SAR能力，仍显示未提供的状态；不以此宣称 M3 科学验收完成。

### PROD-07 / NEXT；若发布 LLM 能力则必需：一个真实模型的端到端验收

- 使用部署者已明确配置并授权的一个端点，按 [LLM 计划](2026-09-14-llm-interface.md) 使用最小合成/可公开事实完成真实生成，记录模型、协议、耗时、usage、缓存外部调用数和错误状态；不读取或展示真实 key。
- 再核对真实来源案例的引用范围、缺证据说明和来源版本；仍标 `llm_inferred`，引用 ID 合法不等于内容正确。
- **关闭依据**：真实生成/缓存复用/引用回跳和失败恢复通过；无配置继续离线。未满足时只交付离线摘要，不写“任意 OpenAI-compatible 模型均可用”。无明确端点时本项保持 not checked，不阻塞其余 CORE 工作。

### PROD-08 / NEXT；仅在开放多人/LAN/托管前必需：认证与项目授权

当前 projects 无 owner、名称全局唯一，项目 API 仅依赖数据库；同名创建会更新已有项目描述。UUID 和 CORS 不是权限机制。

- 在现有应用内定义用户与项目归属、访问检查以及付费模型调用权限；复用适合的已有认证方案，不引入独立服务仅为追随惯例。旧单用户项目有明确归属迁移。
- **关闭依据**：匿名不能读写项目/调用付费模型；用户 A/B 不能互读、互改、互删或用 UUID 越权；同名项目相互独立；部署侧 TLS、秘密管理、数据库隔离与备份恢复验证通过。只提供登录网关的共享团队空间必须明确共享语义，不能宣传为用户隔离。

## 4. 顺序、发布闸门与后置内容

执行顺序：**PROD-04 默认网络修正 + PROD-02 范围修复 → PROD-01 真实来源选择/入库 → PROD-03 项目重开及版本合同 → PROD-04 恢复演练 + PROD-05 发布验收**。真实来源合同与项目版本设计应先协调再迁移；未修复范围错误前不把真实分析输出交付用户。

G1（受控单用户试用）必须逐项证明：

1. 干净安装与来源覆盖说明可按文档完成，数据不是 Demo 冒充真实。
2. 真实公开号→同族→去重结构→证据→结构筛选可用，缺失和错误可解释。
3. 所选/当前结果导出范围准确、科学标识及来源版本保留。
4. 保存→关闭页面→重开项目→重启服务→恢复备份，内容和来源不丢失。
5. 化学回归、来源合同、升级/API、浏览器及声明规模下的性能通过；没有开放 P0/P1。

G2（带活性/LLM 的单用户版本）在 G1 上按公开承诺增加 PROD-06/07。G3（多人托管）再增加 PROD-08。三者分别验收，不能用某次演示或测试总数替代。

**NEXT 增强**：Ketcher 在现有对话框中最小集成，并验证立体结构绘制/编辑→显式查询；Chrome 实际加载 MV3 并验证用户主动传递公开号，Web App 独立可用。**LATER**：大型导出 job、缓存容量策略（按测量启动）、广域搜索、跨同族 SAR、自由聊天、经覆盖评估后的 OCSR。**REJECT**：Espacenet 自动化、无证据科学推断、FTO 定论、新永久面板或分布式设施堆叠。
