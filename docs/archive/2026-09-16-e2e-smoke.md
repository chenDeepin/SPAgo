## Scope kept, shape chosen

One runner, one smoke path: `@playwright/test` (dev dependency, Apache-2.0, §23
decision recorded in `THIRD_PARTY_NOTICES.md` §2 in the same change) driving the MVP
workflow loop of PROMPT.md §13 against the *seeded compose stack* — Playwright does
not boot its own stack, because a test that seeds its own database verifies a
different deployment than the one users run.

- `apps/web/playwright.config.ts` — baseURL `SPAGO_BASE_URL` (default
  `http://127.0.0.1:8000`), one worker, Desktop Chrome project.
- `apps/web/e2e/smoke.spec.ts` — search `DEMO-PATENT-A` → family DEMO-FAMILY-1 and
  its compound table visible → a row opens the evidence inspector and closes →
  `Structure ▾` dialog, aspirin SMILES substructure → the table restates
  `(structure search)` with ≥ 1 row → `Export ▾` → `CSV · Structure results (N)`
  produces a `spago-export.csv` download.
- `npm run test:e2e`; run artifacts (`test-results/`, `playwright-report/`) are
  git-ignored.

## What the first browser run found

The spec originally assumed a row click opens the structure drawer; the real
affordance is the **evidence inspector** (row click) with the structure preview on its
own button. The smoke follows the real UI. No application code changed in this round.

## Deliberate limits

One smoke, not a suite: the Python API tests already own API behaviour; this exists
because only a browser proves the loop. No CI wiring for the smoke yet — CI has no
seeded stack; connecting them is a later, explicit step, not assumed here.
